# OMS 文档仓库设计

日期：2026-07-12

## 目标

将已确认的 OMS 需求、架构决策、模块设计、会话决策和恢复节点集中保存到 GitHub，作为后续讨论和开发的事实来源。

## 采用方案

使用单一文档仓库，按需求、ADR、模块设计、安全、会话记录和追踪矩阵分目录管理。当前阶段不加入业务代码，避免需求设计与实现混杂。

## 仓库结构

- `README.md`：项目入口和文档导航。
- `CURRENT_STATUS.md`：当前冻结状态。
- `NEXT_TASK.md`：下一任务和恢复提示。
- `requirements/`：带编号和状态的需求。
- `adr/`：架构决策记录。
- `module-design/`：模块设计摘要。
- `security/`：文件安全和导入规范。
- `conversation/`：结构化会话决策记录。
- `traceability/`：需求追踪矩阵。

## 维护规则

1. GitHub 是事实来源。
2. 已确认需求使用 `CONFIRMED`。
3. 未确认内容使用 `PROPOSED` 或 `DISCUSSING`。
4. 被否定内容保留并标记 `REJECTED` 或 `DEPRECATED`。
5. 每次讨论结束更新 `CURRENT_STATUS.md` 和 `NEXT_TASK.md`。
6. 进入开发后，所有工作建立 `REQ -> Design -> ADR -> Task -> Code -> Test` 追踪链。

## 范围

本次只沉淀截至第九十八部分已确认的需求和决策。临期库存与批次管理深度仍保留为待讨论项，不擅自冻结。

## 自检

- 无 TBD 或占位符。
- 需求状态和当前讨论一致。
- 未将预售额度混入物理库存。
- 未将 OMS 扩展为 ERP 或完整 WMS。
- 未声称保存逐字完整聊天记录，仓库中保存的是结构化决策摘要。
