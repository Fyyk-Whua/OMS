# OMS 详细需求规格说明书

版本：V0.1  
状态：需求基线草案  
更新时间：2026-07-14

## 1. 文档目的

本文档用于把已经确认的聊天决策、需求编号、架构决策和模块边界整理为可供产品、架构、开发、测试和 Codex 共同执行的需求基线。

本文档采用以下状态：

- `CONFIRMED`：已经确认，可进入设计和开发。
- `PROPOSED`：建议方案，尚未确认。
- `DISCUSSING`：仍需讨论。
- `REJECTED`：明确不采用。
- `DEPRECATED`：曾采用，现已被替代。

## 2. 项目目标

建设一个面向多企业、多店铺、多库存组织的订单管理与运营平台，重点解决：

1. 多渠道订单统一接入、审核和履约编排。
2. ERP、WMS 和 OMS 独立运行模式下的库存协同。
3. 安全库存、渠道库存、共享库存池、预售和组合商品等运营库存策略。
4. 可追溯、可审计、可补偿的库存占用和流水体系。
5. 安全、可解释、可人工确认的文件导入体系。
6. 通过 GitHub 保存需求、ADR、计划、代码、测试和项目上下文，使 Codex 可以持续小步开发。

## 3. 系统边界

### 3.1 OMS 职责

OMS 负责：

- 订单接入、审核、拆分、状态管理和异常处理。
- 库存可售计算、OMS 临时占用和占用释放。
- 预售、渠道额度、安全库存和活动额度等运营策略。
- 履约路径选择和外部系统编排。
- 库存流水查询、审计、异常检测和补偿。
- 文件上传安全检测和业务数据导入任务管理。

### 3.2 ERP 职责

ERP 模式下 ERP 是库存权威，负责：

- 最终库存数量和可销库存来源。
- 销售单创建和正式库存占用。
- ERP 模式下的库存调整和库存调拨。
- 向 OMS 返回成功、明确失败或可查询的业务状态。

### 3.3 WMS 职责

WMS 负责仓内执行，包括拣货、复核、上架、PDA、波次、路径和仓储效率。OMS 不重复建设完整 WMS。

## 4. 多租户与数据权限

### 4.1 组织维度

系统必须至少支持以下数据维度：

- Tenant：租户。
- Enterprise：企业。
- Store：店铺。
- InventoryOrganization：库存组织。
- Warehouse：仓库。
- Area：库区。
- Location：货位。
- SKU：实际库存商品。

### 4.2 权限规则

1. 所有业务数据必须包含租户边界。
2. 企业、店铺和库存组织筛选为空时，只查询当前用户授权范围内的全部数据。
3. 前端下拉框只显示有权限的数据，后端仍必须重新校验。
4. 用户提交未授权的企业、店铺或库存组织参数时，后端应拒绝访问，不得依靠前端隐藏实现权限。
5. 店铺与库存组织为多对多关系，不得按固定一对一建模。

## 5. 履约模型

系统必须通过配置选择履约路径，不允许在业务代码中根据客户名称或系统环境写死。

第一阶段支持以下模型：

1. `OMS_DIRECT`：OMS 独立库存并直接履约。
2. `OMS_ERP`：OMS 发送 ERP，由 ERP 承担后续业务。
3. `OMS_ERP_WMS`：OMS → ERP → WMS。
4. `OMS_WMS_ERP`：OMS → WMS → ERP。

库存来源、正式占用责任方和回调处理方式必须由履约模型及对应 Adapter 决定。

## 6. 商品与组合商品

1. 组合商品在订单审核或履约单生成阶段拆分为实际 SKU。
2. 组合商品本身不建立物理库存。
3. 组合商品可售数量按组成 SKU 的最小可组合数量计算并向下取整。
4. 组合商品占用必须使用同一个 `ReservationGroupId`，全部组成 SKU 占用成功才算成功。
5. 库存流水记录实际 SKU，同时保留原组合商品订单明细和营销策略关联。

## 7. OMS 独立库存模式

### 7.1 功能范围

OMS 独立模式支持：

- 仓库、库区和简单货位管理。
- 库存余额、库存流水和库存调整单。
- Excel 初始化导入。
- 人工调整、简单库存移动和轻量盘点。
- 订单库存占用、释放和实际扣减。

第一阶段不支持：

- 波次、PDA、拣货路径、上架策略、复核流程和仓储优化。
- 负库存。

### 7.2 可销售库区

- 合格品区可参与可售库存计算。
- 退货区、不合格品区、冻结和损坏库存不参与可售库存计算。
- 退货商品只有移动或确认到可销售状态后才可重新销售。

### 7.3 库存初始化

支持：

1. Excel 初始化导入。
2. 通过库存调整单人工初始化。
3. 后续通过受控 Adapter 接口导入。

任何方式都不得直接修改库存余额，必须产生业务单据和库存流水。

## 8. ERP 库存模式

1. ERP 是库存权威。
2. OMS 保存 ERP 库存快照，不把快照当作主库存。
3. ERP Adapter 必须声明返回数量语义：`ON_HAND`、`AVAILABLE`、`SELLABLE` 或 `CUSTOM`，防止安全库存或冻结库存重复扣减。
4. OMS 接单可用数量为 ERP 可销库存减去尚未被 ERP 确认的 OMS 有效软占用。
5. ERP 确认销售单和正式占用后，OMS 将责任方转交 ERP，释放本地软占用并刷新 ERP 快照。
6. ERP 网络超时属于 `UNKNOWN`，不得当作失败立即释放。
7. ERP 明确失败时，OMS 才能释放软占用并将订单转为异常或库存不足状态。

## 9. 统一可售库存计算

所有模块必须调用 `Sellable Inventory Service`，禁止订单、商品、活动或渠道模块分别实现库存公式。

基础计算顺序：

1. 校验租户、企业、店铺、库存组织、仓库、SKU 和当前时间。
2. 过滤冻结、损坏、退货待检、不合格和禁售库存。
3. 扣除有效订单占用、履约锁定、调拨锁定和安全库存。
4. 应用共享库存池规则。
5. 应用渠道额度。
6. 应用活动额度。
7. 单独计算预售额度。
8. 对组合商品执行可组合数量换算。

返回结果必须区分：

- `physicalSellableQty`：现货可售数量。
- `presaleSellableQty`：预售可售数量。
- 数据来源、快照时间和计算状态。

页面不得把现货和预售简单相加显示成物理库存。

## 10. 特殊库存策略

### 10.1 安全库存

- 支持系统、库存组织、仓库、SKU 和仓库+SKU 等范围。
- 多条规则同时命中时，采用最精确规则，不累计扣减。
- 活动和渠道额度不得突破安全库存。

### 10.2 渠道库存

- 支持店铺或渠道额度。
- 渠道可售数量不得大于物理可售数量和库存池可用数量。
- 渠道额度只能限制销售，不能创造库存。

### 10.3 共享库存池

- 多个店铺可以共同使用同一库存池。
- 所有店铺有效占用共同减少库存池可用数量。
- 共享库存池和渠道额度同时存在时取较小值。

### 10.4 冻结库存

- 冻结优先于渠道、活动和预售策略。
- 冻结和解冻必须记录原因、操作人和流水。

### 10.5 虚拟仓和区域策略

- 虚拟仓是运营映射，不是新的物理库存。
- 区域策略用于选择库存组织或仓库，不承担 WMS 拣选优化。

### 10.6 临期和批次

`REQ-INVENTORY-020` 当前为 `DISCUSSING`。在未确认前不得进入第一阶段开发。

## 11. 预售策略

1. 预售属于运营策略，不属于物理库存。
2. 策略包含 SKU、适用组织、预售额度、开始时间、结束时间、预计到货时间和状态。
3. 当前时间达到开始时间后自动上架，达到结束时间后自动下架。
4. 人工取消预售时修改策略状态并保留原额度、已售数量、操作人和原因，不得简单把额度改为 0。
5. 超期、人工取消或到货监测命中任一条件时，停止新增预售。
6. 已有预售订单不因策略失效而自动取消。
7. 到货监测按用户配置的时间窗口内库存净增加量判断。
8. 净增加量达到用户填写阈值时，策略转为 `ARRIVAL_TRIGGERED` 并停止新增预售。
9. 已有订单按审核通过时间 FIFO 进入转现货队列。
10. 到货数量不足以覆盖全部预售订单时，不得一次性全部转换。

## 12. 库存占用

### 12.1 占用类型

至少支持：

- 普通现货占用。
- 预售额度占用。
- 赠品占用。
- 组合商品组成 SKU 占用。
- 调拨锁定。
- 人工业务锁定。

### 12.2 占用状态

建议状态：

`PENDING`、`RESERVED`、`CONFIRMING`、`CONFIRMED`、`RELEASING`、`RELEASED`、`EXPIRED`、`FAILED`、`CONSUMED`、`CANCELLED`。

占用记录不得物理删除。

### 12.3 OMS 独立模式

查询、策略校验、占用记录、库存余额和库存流水必须在同一事务中原子完成。库存不足时整体回滚。

### 12.4 ERP 模式

采用双阶段：

1. OMS 原子创建软占用。
2. OMS 调用 ERP。
3. ERP 成功后责任方转为 ERP。
4. ERP 明确失败后释放 OMS 占用。
5. ERP 结果未知时保留占用，启动查询补偿。

### 12.5 超时策略

支持按店铺、订单类型和占用类型配置超时时间、自动释放规则和超时起算点。

ERP 结果未知状态不得由普通过期任务直接释放。

### 12.6 订单取消

订单取消时必须根据当前 `ReservationOwner` 执行：

- OMS：释放本地占用。
- ERP：调用 ERP 取消或释放接口。
- UNKNOWN：进入补偿和人工接管，不得直接释放。

## 13. 幂等与补偿

1. 重复页面提交、渠道重复推送、MQ 重复投递和 ERP 重复回调不得产生重复占用或扣减。
2. 外部事件必须记录来源、事件编号、事件类型、业务编号、Payload Hash 和处理结果。
3. 补偿任务必须幂等、可重复执行并保留完整日志。
4. 达到最大重试次数后进入 `MANUAL_REVIEW`。
5. 人工释放必须有专门权限、填写原因、二次确认和审计记录。
6. ERP 已确认占用时，人工操作不得只修改 OMS 状态。

## 14. 库存流水和审计

1. 库存余额和库存流水分离。
2. 每次库存变化记录前后数量、变化数量、变化类型、业务对象、操作人和时间。
3. 完成流水不可直接修改和删除，错误通过冲销流水修正。
4. 库存余额和流水必须在同一事务中提交。
5. ERP 同步必须记录同步批次、前后快照和失败明细。
6. 流水长期保留，不做业务归档和自动删除。
7. 可以使用数据库分区和索引优化，但必须保留全历史查询能力。

### 14.1 库存流水页面

筛选条件：

- 日期：默认上个月 1 日至当前日期，可调整。
- 企业。
- 店铺。
- 库存组织。
- SKU、流水类型和业务单号。

企业、店铺和库存组织未选择时，查看授权范围内全部流水。必须使用服务端分页。

## 15. 文件安全网关

所有上传和导入文件必须经过统一 File Security Service：

1. 文件大小限制。
2. 扩展名白名单。
3. MIME Type 校验。
4. Magic Number 校验。
5. 病毒扫描 Provider。
6. SHA-256 完整性摘要。
7. Excel 宏、外部链接和危险公式检测。
8. 隔离区扫描，通过后才允许业务模块读取。
9. 文件访问必须经过租户和权限校验。
10. 文件安全失败必须返回明确失败原因。

业务模块不得直接解析未通过安全检测的文件。

## 16. 统一数据导入中心

导入流程：

`上传 → 安全检测 → 模板校验 → 字段校验 → 业务校验 → 结果预览 → 用户确认 → 正式导入`。

### 16.1 错误反馈

每条错误至少包含：

- Excel 行号。
- 字段名称。
- 原始值。
- 错误类型。
- 明确错误信息。
- 可执行的修复说明。

错误类型至少包括：必填、类型、长度、重复、模板结构和业务规则错误。

### 16.2 部分导入

- 存在错误时，系统不得自动把成功部分写入业务表。
- 用户点击确认时必须明确选择“仅导入成功部分”或“返回修改后重新导入”。
- 默认行为是不导入。
- 用户选择仅导入成功部分后，才可执行部分成功。

### 16.3 导入结果分页

- 默认每页 100 条。
- 下拉选项：100、200、300、500、1000、2000、5000。
- 允许手工输入正整数，例如 6000。
- 非数字提示“请输入有效数字”。
- 小数提示“请输入整数”。
- 0 或负数提示“分页数量必须大于 0”。
- 前后端都必须校验。

## 17. 非功能需求

### 17.1 安全

- 后端强制执行租户和数据权限。
- 敏感配置不得提交到 GitHub。
- 外部回调必须校验签名、防重放并记录 Payload Hash。
- 文件上传必须经过安全网关。

### 17.2 一致性

- 库存余额、占用和流水使用数据库事务。
- 所有异步流程必须有幂等键和补偿机制。
- 网络超时不得被解释为业务失败。

### 17.3 可审计性

高风险操作必须记录：操作人、来源、原因、审批记录、请求编号、IP 和时间。

### 17.4 可维护性

- Adapter 隔离 ERP、WMS 和渠道差异。
- 需求、ADR、任务、代码、测试和提交必须可追踪。
- 小文件、单一职责、明确接口。

### 17.5 性能

- 流水和占用页面使用服务端分页。
- 订单提交不依赖展示缓存完成占用。
- 库存流水可按时间分区但不归档。
- 可售库存缓存必须携带更新时间和状态。
