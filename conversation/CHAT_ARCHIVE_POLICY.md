# Chat Archive Policy

更新时间：2026-07-12

## 目标

本目录除保存结构化决策摘要外，也用于保存项目完整对话记录，便于后续复盘：

- 需求是如何产生的；
- 哪些方案被讨论、否定或调整；
- 每个结论的上下文是什么；
- 项目在不同阶段为何做出特定决策。

## 保存原则

1. 结构化需求、ADR 和模块设计继续作为项目事实来源。
2. 完整对话记录作为历史依据，不直接替代已冻结需求。
3. 对话记录按日期和会话拆分，避免单文件无限增长。
4. 对话中涉及密码、令牌、个人敏感信息和生产凭据时，提交前必须脱敏。
5. 对话中的建议若未明确确认，不自动标记为已确认需求。
6. 后续需求发生变化时，以最新的需求文档和 ADR 为准，但保留原始对话用于复盘。

## 文件命名

建议格式：

```text
conversation/transcripts/YYYY-MM-DD-session-NN.md
```

配套索引：

```text
conversation/transcripts/README.md
```

## 完整性说明

ChatGPT 当前连接无法自动读取账号内所有历史会话的逐字原文。要形成真正完整、逐字一致的历史档案，应使用以下来源之一：

1. 用户从 ChatGPT 导出的会话数据；
2. 用户复制或上传的完整聊天记录；
3. 当前会话中仍可访问的原始消息。

在没有原始导出内容时，只能保存当前可访问文本和结构化摘要，不能将摘要标记为“逐字完整对话”。

## 建议流程

1. 从 ChatGPT 导出或复制完整会话；
2. 上传为 Markdown、HTML、JSON 或纯文本文件；
3. 检查并脱敏敏感内容；
4. 按日期拆分到 `conversation/transcripts/`；
5. 更新会话索引和需求追踪矩阵；
6. 提交 Git 版本记录。
